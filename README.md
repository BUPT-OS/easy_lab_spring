# File System Data Recovery

> **DDL: 2026年6月14日 23:59**

文件系统是操作系统中负责管理持久数据的子系统，负责把用户数据存储到磁盘硬件中，磁盘里的数据并不会丢失，因此可以持久化的保存文件。文件系统的作用包括为用户建立文件、读出、修改，控制文件的读取等等。在硬盘的视角来看，磁盘中的数据实际上是一系列二进制的数据块，而不同类型文件系统的区别在于这些数据内部的组织形式，即建立索引文件的数据结构之间的区别。这些数据结构大概包括两个部分：一部分数据结构用来索引文件的信息，另一个数据结构则用于通过文件的信息来索引文件的数据。

文件系统的种类有很多，而且有各自的特点。本次lab的目的是以 FAT32 文件系统为例、通过数据恢复的场景让同学们对文件系统的存储机制有更深入的理解。


## 1. FAT32文件系统简介

FAT（File Allocation Table，文件分配表）文件系统是一种由微软发明并拥有部分专利的文件系统，它的发展过程经历了 FAT12、FAT16、FAT32 三个阶段，目前主要应用在移动存储设备中，比如SD卡、TF卡等。本次 lab 涉及到 FAT32 文件系统。

### 1.1. FAT32文件系统结构

有关 FAT32 文件系统的资料有很多，并且非常详细，因此本文档只会简要介绍 FAT32，更加详细的内容可以阅读参考资料：**[1]**, [2]。

对于 FAT32 文件系统来说，整个存储设备大概可以分为 3 个部分：保留区（包含引导）、FAT表、数据区（目录和文件）。

![fat32](./img/image.png)

引导扇区是 FAT32 文件系统的第一个扇区，它包含了有关文件系统的基本信息，比如每扇区字节数、每簇扇区数、FAT表个数等等。除了引导扇区外，FAT32 在保留区中增加了一个 FSINFO 扇区，用以记录文件系统中空闲簇的数量以及下一可用簇的簇号等信息，以供操作系统读取。

位于保留区后的是 FAT 区，由两个或多个完全相同的 FAT（File Allocation Table， 文件分配表）表组成（其数量可以通过读取引导扇区来确定），FAT 文件系统的名字也是因此而来。对于文件系统来说，FAT表的作用是描述簇的分配状态以及标明文件或目录的下一簇的簇号。这里所说的"簇"是一组连续的扇区，扇区的数量同样需要读取引导扇区来确定。所有簇从 2 开始进行顺序编号，每个簇都有一个自己的地址编号。2 号簇的起始位置就是数据区的起始位置。

数据区是真正用于存放用户数据的区域，使用簇为单位来管理。数据包括目录和文件两部分，均使用簇保存。如果目录/文件超过了一个簇的大小，则会使用多个簇存储，使用 FAT 表来存储簇之间的关系，具体方法是使用簇号拿到 FAT 表中对应的表项，该表项即下一个簇的簇号。

对于目录来说，根据结构不同可以将目录项大致分为四种：卷标目录项、"."目录项和".."目录项、短文件名目录项、长文件名目录项。短文件名目录项和长文件名目录项是最重要的数据结构，其中存放着有关子目录或文件的文件名、属性、起始簇号、时间值以及内容大小等信息。在 FAT32 文件系统中，将子目录看作是一种特殊的文件。由于短文件名目录项延续使用DOS时代"8.3格式"文件命名的规则，并且不区分大小写，因此引入长文件名目录项来解决长文件名和区分大小写的问题。目前的 FAT32 文件系统，在为文件分配短文件名目录项的同时还会为其分配长文件名目录项，而且考虑到兼容性问题，并没有废弃短文件名目录项。

> 请阅读[1]、[2]理解 FAT32 中的数据结构。

> "8.3格式"命名规则： 8 个字符的名字加上 3 个字符的扩展名。

通常情况下，2 号簇保存根目录的信息，因此，在理解了 FAT32 文件系统数据结构之后，就可以从 2 号簇开始遍历整个文件系统中的数据。

### 1.2. 实现原理

本节从文件的创建、数据写入、文件删除等操作流程来理解 FAT32 文件系统的基本实现原理。

1. 文件创建：创建文件或目录时，会先在当前目录所在位置的目录项中添加一个目录项，该目录项会记录文件的起始簇号，创建、修改时间、文件属性等信息。

2. 文件修改：如果文件当前的簇空间写满了，系统会查找一个空闲簇，数据将继续写入到该空闲簇中，FAT表中该空闲簇会被标记已经被使用，同时，该文件的结束簇号也会往后移动一个簇。除此之外，还会更新该目录项中的修改时间、文件大小等信息。

3. 文件读取：通过目录项，找需要读取文件所在的开始簇位置。如果文件大于一个簇，则从FAT表中索引下一个簇的编号，顺着这个簇链一直读取，直到结束簇出现。

4. 文件删除：目录中该目录项的信息并不会被删除，而是将该目录项标记为删除状态，其次将 FAT 表中该文件所占用的簇号对应的表项都标记为0，表示未使用。该文件所在簇号所对应扇区的实际文件数据不会被擦除，文件里面的数据仍然存在，只有在下一次创建新文件或者写入新数据时才有可能覆盖或是擦除。

## 2. 实验内容

在实际生产环境中，文件系统误操作是导致数据丢失的常见原因之一。通常，误操作之后只能记下文件名称，并不确定文件路径。本lab的实验内容就是让同学们基于上一节中对 FAT32 文件系统的理解、实现对误删数据的恢复。

### 2.2. 代码说明

本lab的实验代码包含两个文件：

* `FAT32.h`: 定义 FAT32 文件系统中重要的数据结构，包括引导扇区、短文件名目录项、长文件名目录项等等。
* `recover.c`: 实现数据恢复的主要逻辑。

在 `FAT32.h` 文件中，你需要完善 `struct long_name_dir_entry` 的数据结构定义，之后需要在 `recover.c` 文件中实现数据恢复的逻辑。正如前文所说，从根目录簇开始可以遍历整个 FAT32 文件系统的数据。因此，在 `recover.c` 中可以使用 DFS（深度优先搜索）或 BFS（广度优先搜索）来寻找被删除的文件。

大概思路如下：

1. 遍历目录项，从被删除的目录项中拿到被删除的文件名；
2. 如果被删除的文件名匹配，则读取目录项中的起始簇号；
3. 根据文件大小，读取被删除文件的所有簇；

> 注意：在 FAT 文件系统中数据的存储是以小端模式存储的，这与 X86 架构处理器的字节序相同，因此数据可以直接解析，而对于使用大端存储的处理器来说，需要对文件系统镜像中的数据进行字节序转换。

## 4. 辅助工具

结合 lab1 中学习到的 gdb 调试方式，本lab同样可以使用gdb进行调试。参考命令如下：

```bash
gdb --args ./recover ./fat32.disk test.txt recovered_data.txt
```

hexdump[3] 是 Linux 下的一个二进制文件查看工具，它可以将二进制文件转换为ASCII、八进制、十进制、十六进制格式进行查看。因此，在本 lab 中，可以使用 hexdump 工具直接读取文件系统镜像，然后分析数据。参考命令如下：

```bash
hexdump -C ./fat32.disk > a.txt
```

fsck.fat[4] 是 Linux 下用于检查和修复 FAT 文件系统（FAT12 / FAT16 / FAT32） 的工具，属于 dosfstools 套件。使用 fsck.fat 工具可以查看文件系统的基本参数，比如每簇扇区数、保留扇区数、FAT 表数量等等。参考命令如下：

```bash
fsck.fat -v fat32.disk
```
